# ブラウザ選定: 既存Edge vs Playwright同梱Chromium

MEGATransferのアップロード処理で起動するブラウザについて、配布先PCにプリインストールされた
Microsoft Edgeを使う現行方式と、Playwright同梱のChromiumを使う方式を比較した記録。

対象コード: `service/mega_uploader.py`

```python
browser = p.chromium.launch(channel="msedge", headless=self.headless)
```

## 結論

**現状維持（既存Edgeを使用）** とする。

決め手は運用制約（院内共用PC・管理者権限なし・インターネット経由のブラウザダウンロード不可）。
この環境ではChromium同梱による配布サイズ増（約150〜200MB）とビルド手順の複雑化が、
得られるメリットに見合わない。

## 前提の訂正: 「クリーンな環境」論について

「Playwright同梱のChromiumはクリーンな環境なので安定する」という一般論は、本アプリには
ほぼ当てはまらない。

`launch()`（`launch_persistent_context()` ではない）は毎回**一時ディレクトリに新規プロファイルを
作成**して起動するため、普段使いのEdgeのCookie・拡張機能・履歴は一切引き継がない。既存のEdge
ウィンドウが開いていても衝突しない。

したがって「Chromiumの方がクリーン」という差は実質存在しない。実際の差は下表の3点に絞られる。

## 比較

| 観点 | 既存Edge (`channel="msedge"`) | Playwright同梱Chromium |
|---|---|---|
| 配布サイズ | 増加なし | +約150〜200MB（ブラウザ本体の同梱が必要） |
| 配布先での導入 | 不要（プリインストール前提） | ビルドPCで取得したブラウザ一式を同梱する必要あり |
| バージョン固定性 | ✗ Edgeが自動更新される。Playwrightが想定するバージョンと乖離すると壊れる可能性 | ✓ ビルド時のバージョンで固定。挙動が再現する |
| 組織ポリシー(Intune/GPO)の影響 | ✗ 受ける。レジストリHKLM由来のためプロファイルを分けても回避不可 | ✓ 受けない |
| Edge未導入/古いPC | ✗ 起動失敗 | ✓ 影響なし |
| 実行時の動作安定性 | 実質同等（どちらもChromiumエンジン、CDP経由） | 実質同等 |

## 各方式のメリット・デメリット

### 既存Edgeを使う（現行方式）

**メリット**

- 配布物が小さい。ブラウザ本体を含めないため、USB・共有フォルダ・メール添付いずれの配布経路にも乗る
- 配布先PCでのセットアップ作業が不要。管理者権限もインターネット接続も要らない
- ビルド手順が単純（`build.py` の現行構成のまま）

**デメリット**

- Edgeの自動更新でPlaywrightとのCDP互換が崩れ、ある日突然動かなくなる可能性がある
- 組織ポリシー（強制サインイン、拡張機能の強制インストール、起動時ページの強制表示など）の
  影響を受ける。新規プロファイルでも回避できない
- Edgeが未導入、またはバージョンが極端に古いPCでは起動に失敗する

### Playwright同梱Chromiumを使う

**メリット**

- ブラウザのバージョンをビルド時点で固定でき、動作が再現する
- 組織ポリシーの影響を受けない
- 配布先PCのブラウザ環境に依存しない

**デメリット**

- 配布サイズが約150〜200MB増える
- `--collect-all playwright` では**ブラウザ本体は同梱されない**。ブラウザは
  `%LOCALAPPDATA%\ms-playwright` に配置されるため、`PLAYWRIGHT_BROWSERS_PATH=0` を指定した
  インストールと `--add-data` による明示的な同梱、または実行時の環境変数設定が別途必要になる
- ブラウザ更新（脆弱性対応を含む）にはアプリの再ビルドと再配布が必要になる

## 切り替えを検討すべきサイン

以下が発生した場合、Chromium同梱への移行を検討する。

1. Edge更新後に `launch()` が失敗する／要素検出が壊れる、が繰り返される
2. 配布先PCで組織ポリシーによりEdgeの自動化が阻害される
3. Edge未導入またはバージョンが極端に古いPCが配布対象に入る

## 採用しなかった案

**ハイブリッド（msedgeで起動を試み、失敗したら同梱Chromiumにフォールバック）**

技術的には可能だが、結局Chromiumを同梱する必要があるためサイズ面のメリットが消え、
起動処理も複雑になる。実際に問題が発生していない現時点では採用しない。

## 未確認の前提

以下は判断の前提として未確認。状況が変われば結論も変わりうる。

1. 配布先PCのEdgeがIntune等で組織管理されているか。管理されている場合、将来ポリシーによって
   自動化がブロックされる可能性があり、Chromium同梱の優先度が上がる
2. 配布方法とサイズ制約。USB・ファイル共有での手渡しなら200MB増は許容しやすいが、メール添付や
   容量制限のある共有フォルダ経由では厳しい
3. Edgeの自動更新が原因で動作しなくなった実績の有無。あれば現状維持の前提が崩れる
